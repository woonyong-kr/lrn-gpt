# run 112 실험 보고서

## 이번 가설

epoch를 실제 optimizer update 수로 환산할 때 생기던 반올림 경계 문제를 고친 뒤, seed202의 mish + stride24 설정을 정확한 105 update 상당의 epoch 값으로 다시 검증한다. 기준은 `105 / 39 = 2.6923076923076925 epochs`다.

## 왜 이 가설을 세웠는가

run111은 epoch 옵션이 동작하고 raw validation loss를 낮출 수 있음을 보여줬지만, `2.692308 * 39 steps_per_epoch`가 ceil 경계에 걸려 의도한 105 update가 아니라 106 update로 실행됐다. 이후 epoch-to-update 변환 코드에서 아주 작은 epsilon을 빼도록 보정했으므로, 같은 seed202 설정을 정확한 `105/39` epoch 값으로 재실행해 반올림 artifact와 학습 길이 효과를 분리했다. 모델 구조는 413,184 parameter mish Transformer, `stride=24`, 동일 optimizer, 동일 regularization으로 고정했다.
